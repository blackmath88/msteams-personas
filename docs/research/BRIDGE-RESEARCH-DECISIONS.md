# Assistant-bridge research disposition

Date: 2026-10-29. Input: user-supplied Perplexity architecture/UX review, “Pasted text(2).txt”. This is a decision summary, not independent verification of that report's hosting prices or protocol claims.

## Adopt

- Manual template adaptation remains the default. The bridge is a supported secondary path for new situations.
- Three-to-five-slide sequences are the useful unit; a course can contain ordered sequences.
- Modest normalization: stable shared entities, scene-local messages, explicit complete state for objects included in each snapshot; no inheritance or patch chains initially.
- A new-project compiler adapter reuses current renderer view models without injecting imported content into global catalogues.
- Editable recommendation, boundary and facilitator notes are first-class requirements.
- Preserve preparation-session context; generate packs from actual supported capabilities.
- Storyboard discussion is optional when a trainer explicitly chooses defaults.
- Resolve reference errors visually when possible; offer external repair as an option.
- Share export preparation as well as composition so density/crop behaviour does not drift.
- Same semantics across routes, staged integration maturity.

## User acceleration

The next attempt combines manual authoring and the AI-assistant bridge rather than delivering them as separate long phases. Use the 30-minute task. Parallel implementation is optional and bounded; the shared contract and final integration remain coordinator-owned.

## Retain as hypotheses

Low-friction bridge completion, cross-assistant reliability, ideal pack size and naming. Validate through actual observed trainer tasks; fixtures and self-review cannot establish user success.

## Defer

Public rendering service, queues, remote MCP, in-site AI and editable native PPTX shapes. WebMCP can be a small progressive enhancement after the core path works. Do not block the bridge on hosting choices.

## Verification boundary

No current price, SDK version or browser-support claim from the external report is frozen into the build. Verify primary sources when those implementation decisions become relevant.
